# What

- CONTRIBUTING: claim an issue and wait to be assigned before opening a PR.
- PR template and PR quality check require an **Issue** section with `#N` (`Fixes` / `Refs`). Titles may use `[no-issue]` for maintainer work with no tracking issue.
- Studio UI PRs (`studio/` `.tsx` / `.css` / …) must include a **UI** section with screenshots or a short video. Titles may use `[no-ui]` when there is no visible UI change.

# Why

People were opening PRs without claiming issues, which caused duplicate work and made reviews hard to tie back to a tracked task. UI changes without media are hard to review.
